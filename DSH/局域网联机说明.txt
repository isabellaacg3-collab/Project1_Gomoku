 一、现状：目前 LAN 模式是什么状态
------------------------------------------------------------------------

  工程里与 LAN 有关的东西只有两处占位，没有任何实际实现：

    StartMenu.cpp:18   画出 "LAN(coming soon)" 的框，但主循环里
                       这个框**没有点击响应**，点了没反应。
    main.cpp:21        枚举里有一个 LAN_GAME 状态，但从未被赋值、
                       也从未被判断过（等于死代码）。

  另外两处值得注意的既有设计，联机模式应该沿用同样的套路：

    main.cpp:32        AI 走子的判断条件是
                       "gamestate == AI_GAME_EASY && currentPlayer == 2
                        && !roundOver && !gameOver"
                       联机模式也应该用"轮到谁 / 己方是哪一方"这类条件
                       来驱动，而不是每帧都发数据。
    main.cpp 的难度面板 drawDiffPanel() 给出了"二级菜单"的写法，
                       LAN 的"创建房间 / 加入房间"可以照抄这个结构。


------------------------------------------------------------------------
 二、三档实现方案（按工作量从小到大，建议先做方案 A）
------------------------------------------------------------------------

  方案 A：最小可用联机（推荐先做这个）
    形态：一台机器当"房主(host)"，另一台"加入(join)"，双方各下一色。
    通信：TCP，一条连接，双向收发。
    同步：房主是唯一权威，负责判定合法性与胜负；加入方只负责发自己的
          落子、收房主广播的结果。
    工作量：约 300~500 行新代码（新增一个 lan.cpp 即可）。
    验收标准：两台机器（或同一台开两个窗口）能完整下完一盘，
              双方棋盘一致、胜负判定一致、能正常退出。

  方案 B：在 A 的基础上加"断线与重连"
    增加：连接状态显示、心跳、掉线提示、重新连接、中断后恢复对局。
    增加：可选的"悔棋请求 / 同意"这类需要双方确认的消息。
    工作量：再增加 150~250 行。

  方案 C：观战 / 房间列表 / 多人房间
    形态：一台服务器进程，多个客户端；房主+对手+若干观战者。
    要点：消息里加"座位(side)"字段，观战者只收不发；
          需要一个简单的房间列表协议（或者用 UDP 广播自动发现房间）。
    工作量：明显上升，属于加分项，不是必须。

  不建议的做法：
    两台机器各算各的棋、只交换落子、各自判定胜负（"对等同步"）。
    只要双方规则判断有任何一处不一致（例如长连、边界），就会永久
    不同步，而且很难排查。**由房主单方面判定再广播**是最省心的。


------------------------------------------------------------------------
 三、技术选型建议
------------------------------------------------------------------------

 3.1 用 TCP 还是 UDP？
     建议 TCP。五子棋是"回合制、低频、每条消息都不能丢"的场景，
     TCP 自带重传与顺序保证，不用自己处理丢包和乱序。
     UDP 只有在做"实时对战 + 自己实现可靠层"时才划算，本场景没必要。
     注意：TCP 是字节流，**不保证一条 send 对应一条 recv**，
     所以必须自己定"消息边界"（见 4.3 的按行读取）。

 3.2 网络库选哪个？
     推荐：直接用 Windows 自带的 Winsock2（winsock2.h）。
       - 不需要额外安装任何东西，MinGW 已自带（本机已验证）；
       - 链接时加一个库：-lws2_32。
     可选：SDL_net。它跨平台、接口更简单（SDLNet_TCP_Open 等），
       但要多一个 dll，而且本工程只要求 Windows，收益不大。
     不建议：Boost.Asio。功能强大但对课程作业太重，
       编译慢、模板报错难懂，会吃掉大量时间。

 3.3 本机环境实测结论（我已实际编译验证过，可直接照抄）
     - winsock2.h / ws2tcpip.h 存在，libws2_32.a 存在；
       WSAStartup(MAKEWORD(2,2)) 返回 0，版本 2.2，socket() 可用。
     - select() 带 100 毫秒超时查询监听套接字，三次都立刻返回 0，
       说明**不会阻塞**，可以安全地放在游戏主循环里每帧调用。
     - ioctlsocket(s, FIONBIO, &1) 返回 0，非阻塞模式可用。
     - std::thread 在本机 MinGW 4.9.2（posix 线程模型）下**不需要额外
       链接参数**即可编译运行；如果加上工程的 -static 参数，
       需要补一个 -pthread（实测 -pthread -static 组合正常）。

 3.4 端口与地址
     - 默认端口建议 8888（固定端口便于口口相传）；
       想更稳妥可以让房主支持改端口，或让系统自动分配后显示出来；
     - 添加/加入时，让用户输入 "192.168.x.x:8888" 这样的字符串，
       用 inet_pton / getaddrinfo 解析即可，不必做输入框控件；
     - 房主界面上应把**本机 IP 显示出来**（gethostname +
       gethostbyname 取第一个非 127.0.0.1 的地址），方便对方输入；
     - 用 ipconfig 查 IP 比依赖主机名解析更可靠。

 四、建议的通信协议（自己定的一套小协议）
------------------------------------------------------------------------

 4.1 消息格式：文本行协议
     建议用**纯 ASCII 的文本行**，每条消息以 '\n' 结尾，形如：

         JOIN 1\n            加入方 -> 房主：我要求执黑(1)
         WELCOME 2\n         房主 -> 加入方：你执白(2)，对局开始
         MOVE 7 8\n          某一方落子在第 7 行第 8 列
         BOARD ...\n         房主 -> 加入方：整盘棋数据（用于同步/重连）
         RESET\n             开始新的一局
         BYE\n               正常退出
         PING\n / PONG\n     心跳，用来发现对方掉线

     为什么用文本而不是二进制：
       - 肉眼可读，用 printf 就能调试，出错时一眼看出是哪条消息；
       - 不用考虑字节序（大小端）问题；
       - 一条消息很短，多几个字节完全不影响性能。
     强烈建议：**协议里只用 ASCII 字符，不要放中文**。
       两端机器的系统区域设置可能不同，中文会引出 GBK / UTF-8
       的编码问题（这也是本次交付文件都用 GBK 的原因）。

 4.2 谁是权威（重要）
     房主(host)是唯一权威：
       - 收到对方的 MOVE 后，由房主检查该点是否为空、是否轮到他；
       - 合法才真正落子，然后把结果广播回去（也可以直接回 OK/ERR）；
       - 胜负判定只在房主这一侧做，判定结果广播给加入方。
     加入方(client)：
       - 自己落子前先做一次本地预检（越界、已占位），减少无效往返；
       - 以房主广播的结果为准，不自己宣布胜负。
     这样即使两端规则实现有出入，也永远以房主为准，不会永久不同步。

 4.3 按行读取（TCP 流式处理的要点）
     必须自己维护一个接收缓冲区，把收到的字节攒起来，按 '\n' 切分，
     最后一段不完整的留在缓冲里等下次数据。伪代码思路：

         recv 到临时缓冲 tmp
         把 tmp 追加到 g_recvBuf
         while(g_recvBuf 里能找到 '\n'){
             取出第一行 -> 交给 handleMessage()
             从 g_recvBuf 中删掉这一行
         }

     不要假设"一次 recv 正好等于一条消息"，这是新手最常见的坑。

 五、建议的代码结构（怎么接进现有工程）
------------------------------------------------------------------------

 5.1 新增一个 lan.cpp / lan.h，把网络细节全部关在里面
     建议对外只暴露这几个函数（名字仅供参考）：

         bool lanInit();                      初始化 Winsock
         bool lanHost(int port);              开房并等待对方加入
         bool lanJoin(const char *ip, int port);  加入别人的房间
         void lanTick();                      每帧调用一次：收发+解析
         void lanSendMove(int row, int col);  发出自己的落子
         bool lanPollMove(int &row, int &col);取出一条"对方落子"事件
         bool lanConnected();                 是否还连着
         void lanClose();                     断开并清理

     关键设计：网络层**不直接调用 placeChess()**，
     而是把"对方下了一步"作为一个事件交回主循环处理。
     这样网络与游戏逻辑解耦，主循环仍然是唯一的落子入口，
     不会出现"网络线程和主线程同时改棋盘"的麻烦。

 5.2 主循环怎么接（照抄 AI 的写法）
     在 main.cpp 的 for(;is_run();delay_fps(60)) 里，每帧加一行：

         if(gamestate == LAN_HOST || gamestate == LAN_GAME){
             lanTick();                 /* 非阻塞，不会卡帧 */
         }

     然后用与 AI 完全相同的三段式处理对方的落子：

         int row, col;
         if(lanPollMove(row, col)){
             placeChess(row, col, currentPlayer);
             if(!checkWin(row, col, currentPlayer)){
                 switchPlayer(currentPlayer);
             }
         }

     自己落子时，在 placeChess 之后补一句 lanSendMove(row, col)。

 5.3 需要改动的点（都很小）
     - main.cpp 的 GameState 枚举：把没用的 LAN_GAME 保留，
       再加两个状态，例如 LAN_MENU、LAN_HOST、LAN_JOIN；
     - StartMenu.cpp：让 "LAN" 那个框真正响应点击（现在只是画出来），
       进入一个"创建房间 / 加入房间"的二级面板（可照抄 drawDiffPanel）；
     - main.cpp 的鼠标分支：增加 LAN 相关状态的按钮判断
       （按钮坐标可继续沿用 280~520 / 220~270 这一套）；
     - Makefile.win 的 LIBS 里加 -lws2_32；
       若把 lan.cpp 用 std::thread，再补 -pthread；
     - Dev-C++ 工程文件里加入 lan.cpp 这个单元。

 5.4 一个必须注意的坑：头文件顺序
     windows.h 会引入旧的 winsock.h，与 winsock2.h 冲突。
     规则是：**winsock2.h 必须写在 windows.h 之前**。
     而 EGE 的 graphics.h 依赖 Windows 头，所以 lan.cpp 里应当：

         #include <winsock2.h>     /* 必须放最前 */
         #include <ws2tcpip.h>
         #include <graphics.h>      /* 之后才包含 EGE */

     如果出现大量 "重定义" 报错，几乎都是这个顺序问题。

 六、两种收发方式，选一种即可
------------------------------------------------------------------------

 方式 1（推荐，简单）：单线程 + 非阻塞轮询
     - 套接字用 select() 设 0~100 毫秒超时，每帧查一次有没有数据；
     - 没有网络数据时 select 立刻返回，不会卡住画面；
     - 好处：不需要线程、不需要加锁，棋盘只被主线程碰，
             不存在数据竞争，最容易做对。
     - 代价：延迟取决于帧率（60 帧时约 16 毫秒），
             这个量级对回合制棋类完全无感。
     结论：**五子棋这种回合制游戏，优先选方式 1**。

 方式 2（进阶）：后台线程专门收发 + 队列交给主线程
     - 开一个 std::thread 阻塞 recv，把解析出的消息压进队列；
     - 主线程每帧从队列取消息处理；
     - 必须给队列加锁（std::mutex），否则会出随机崩溃；
     - 好处：能第一时间收到数据，也便于实现心跳超时检测；
     - 代价：多线程调试成本明显上升，MinGW 下还要配 -pthread。
     除非要做到"掉线立刻感知"这类需求，否则没必要。

 七、健壮性：出错时怎么办
------------------------------------------------------------------------

  7.1 对方掉线
      - 方式 1 下，recv 返回 0 表示对方正常关闭，返回 SOCKET_ERROR
        表示连接异常，两种情况都应该：提示"对方已断线"、
        回到菜单、并把棋盘状态清掉（避免继续下一盘时状态错乱）。
      - 也可以用心跳：每隔 3 秒发一条 PING，超过 10 秒没收到 PONG
        就判定掉线。

  7.2 不同步
      - 每条 MOVE 消息里可以带一个"第几手"的序号，收到时对不上
        就说明双方已经不同步；
      - 补救办法：房主发一条 BOARD 消息把整盘棋推过去，
        加入方清空棋盘并按这个数据重画。
      - 棋盘 15×15=225 个格子，用 225 个字符就能表示（'0'/'1'/'2'），
        一条消息两百多字节，重传成本可以忽略。

  7.3 失败的常见原因（自查清单）
      - 防火墙拦截：第一次运行时 Windows 会弹窗询问，必须点"允许"；
      - 两台机器不在同一网段（比如一台连手机热点、一台连路由器）；
      - 用了 127.0.0.1 去连另一台机器（那是本机回环地址，连不到别人）；
      - 端口被占用或输入错；
      - 忘了调 WSAStartup，socket 全部失败；
      - 拿工程现有的 .exe 直接跑却忘了重新编译（改动没进去）。

 八、怎么测试（不用两台电脑也能测）
------------------------------------------------------------------------

  1. 单机双开：把编译出的 exe 复制两份，一份当房主、一份当加入方，
     地址都填 127.0.0.1，端口相同，就能在一台机器上跑通整盘棋。
     这是最省事的调试方式，建议先把这条路走通。
  2. 局域网实测：两台电脑连同一个路由器，房主界面显示自己的
     192.168.x.x，加入方照抄。注意双方都要放行防火墙。
  3. 异常测试：
     - 对局中途直接关掉一方的窗口，看另一方是否给出提示并回到菜单；
     - 故意输入错误的 IP 或端口，看是否明确报错而不是卡死；
     - 连续开多盘（RESET），看胜负计数与棋盘是否正确清零。

 九、建议的实施顺序（把风险摊开）
------------------------------------------------------------------------

  第 1 步：先不管界面，写一个命令行小程序验证"能连上、能收发一行字"。
          这一步跑通，最大的未知（防火墙、IP、端口）就排除了。
  第 2 步：实现文本行协议的收发框架与消息切分（4.3 的缓冲逻辑）。
  第 3 步：接入游戏逻辑——只做"双方轮流落子 + 胜负广播"，
          先不做新局、悔棋、断线。
  第 4 步：补 UI（LAN 二级菜单、连接状态提示、本机 IP 显示）。
  第 5 步：补健壮性（掉线提示、心跳、BOARD 重同步）。
  第 6 步（可选）：房间列表、观战、悔棋请求。

  按这个顺序，每一步都有可运行的成果，不会写到一半发现方向错了。


------------------------------------------------------------------------
 十、如果不想投入太多：退一步的"近似联机"方案
------------------------------------------------------------------------

  如果时间紧张，还想拿到联网部分的印象分，可以考虑：

    - 本机双人对弈已经有"本地双人"了，价值有限；
    - 更有性价比的是**"同屏轮流 + 存档交换"**：
      一盘棋下到一半，把棋盘状态存成一个文本文件，
      通过 U 盘 / 聊天软件传给对方，对方载入后继续下。
      它不需要任何网络编程（正好复用"存盘续玩"那一项功能），
      虽然不算真正的联机，但演示效果直观、风险极低。
    - 这个方案可以和真正的 LAN 模式并存：LAN 是目标，
      存档交换是有把握的保底。
