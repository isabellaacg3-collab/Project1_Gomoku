------------------------------------------------------------------------
 二、普通模式（ai_normal.cpp）实现的逻辑
------------------------------------------------------------------------

  决策优先级从高到低共四步：

   1. 空棋盘            -> 直接走天元（中心点）。
   2. 我能一步成五      -> 立刻落子获胜（必杀）。
   3. 对手能一步成五    -> 立刻占住那个点（必堵）。
   4. 都不是            -> 对每个候选空点算综合分，取最高分：
                            进攻分 = 我若下这里，四个方向形成的棋型分之和
                            防守分 = 若对手下这里，他能形成的棋型分之和
                            综合分 = 进攻分 + 0.9 × 防守分

  这就是它比简单模式强的原因：第 3 步会主动堵对手的成五点，第 4 步的
  防守分又会让它去破坏对手的活三 / 冲四。简单模式完全不看对手的棋。

  棋型分值表（关键，量级关系比具体数字更重要）：
      五连 100000  >>  活四 18000  >  冲四 2200 > 活三 2000
      >  眠三 220  >  活二 200  >  眠二 30  >  孤子 2

  棋型判定方式：对某个候选点，沿横、竖、两条斜线四个方向，
  分别统计"连子数"与"两端是否开放（能再落子）"，再查表得分。
  只按单方向求和，不识别双活三等组合棋型——这是它停留在"普通"档的原因。

  候选点优化：只考虑贴着已有棋子（周围 2 格内有子）的空点，
  把 225 个点压到几十个，既快又符合棋理。


------------------------------------------------------------------------
 三、困难模式（ai_hard.cpp）实现的逻辑
------------------------------------------------------------------------

  核心是 Minimax（极小极大）博弈搜索 + Alpha-Beta 剪枝。

 1) Minimax 的思想
    把对局看成一颗博弈树。双方都"理性"：
        叶节点           -> 用评估函数给局面打分
        MAX 层（我方走） -> 在所有子节点中取最大值（我挑最好的）
        MIN 层（对手走） -> 在所有子节点中取最小值（对手挑让我最差的）
    根节点最终选中的那一步，就是"假设对手也会最优应对时，对我最好的着法"。
    这就是"算杀"能力的来源：它能看到"我走这里 -> 对手必然那样应 ->
    我再这样杀"的连续线路，而不只是眼前一步。

 2) Alpha-Beta 剪枝
    纯 Minimax 节点数随深度指数增长（分支因子 b、深度 d 时约 b^d），
    15×15 棋盘根本搜不动。Alpha-Beta 在数学上不改变 Minimax 的结果，
    却能砍掉大量不影响最终决策的分支。它维护两个边界：
        alpha = MAX 层目前已经保证能拿到的最好分值（下界）
        beta  = MIN 层目前已经能把对手压到的最差分值（上界）
    剪枝条件（MAX 层）：某个子节点返回值 v >= beta，说明这一步好到
    "对手在上一层绝不会允许走到这个局面"，于是剩下的兄弟节点
    再也不用看，直接返回。MIN 层对称（v <= alpha 时同样可以返回）。

 3) 让剪枝真正有效的三个工程手段
    a. 着法排序（最重要）：先搜高分着法，能尽早收窄窗口。
       排序用的是"我方在此点的进攻价值 + 对手在此点的威胁价值 × 1.1"。
    b. 候选点与分支限制：只考虑棋子附近的空点，每层取前 N 个着法
       （根节点 TOP 16，内部节点 TOP 10）。
    c. 置换表：同一局面可能经由不同着法顺序到达，缓存已算过的结果。

 4) 速度与正确性的两个关键实现
    - 增量评分：维护双方全盘棋型分，落子 / 撤销时只更新受影响的
      四个方向，而不是每个叶节点重算全盘。这是搜索能跑完的前提。
    - 胜负分与评估分量纲分离：真正的输赢用 WIN_SCORE(1000000) 表示，
      并"减去搜索层数"，使越快取胜的线路分越高（3 步杀优于 5 步杀）；
      静态评估分被限制在 ±LEAF_VALUE_CAP 内，绝不会冒充胜负分。

 5) 其它
    - 迭代加深：从深度 1 逐层加深到 MAX_DEPTH(4)，并设 1 秒时间预算，
      被打断时也有可用的着法。
    - 快速战术预判：先查"我能否一步成五""对手能否一步成五"，直接返回，
      不用把明显的杀招交给搜索慢慢找。
    - 评估函数取防守权重 1.05（略偏防守），与普通模式的 0.9（偏进攻）不同。

 6) 实测剪枝效果（同一局面跑两次的对比数据）
        防守活三   深度4：开剪枝 1384 节点 / 219 次截断，纯 Minimax 14734  -> 约 1/10.6
        追杀活三   深度3：开剪枝  252 节点 /  30 次截断，纯 Minimax  1768  -> 约 1/7.0
        复杂中局   深度4：开剪枝  946 节点 / 271 次截断，纯 Minimax 17744  -> 约 1/18.8
    两者着法完全一致，印证了"Alpha-Beta 不改变结果、只砍无用分支"。

 7) 不含禁手：不做三三禁手、四四禁手、长连禁手判定。
    连成五子及以上即算胜，与工程原有 checkWin 的 count >= 5 一致。

 四、让简单模式 AI 略微更聪明的修改建议
------------------------------------------------------------------------

  先说明简单模式当前的问题（都在工程原有 AI.cpp 里）：

    Q1. getScore() 只评估"自己下这里能连成几子"，完全不看对手的棋，
        所以它永远不会去堵对手的活三 / 冲四。
    Q2. getScore() 只从"紧邻的第一格"开始看：若第一格是空的就直接
        break、返回 0 分。于是空盘或散点阶段几乎所有点都是 0 分。
    Q3. chooseEasyMove() 的 bestScore 初值为 0，且用大于号比较
        （tempScore > bestScore）。结合 Q2，开局所有点同分，
        结果总是落在棋盘最左上角的第一个空点，不会占天元。
    Q4. countMultiple 数组只有 11 个元素，而 count 是整条线的连子数，
        没有上限保护，长连时存在越界读的隐患。
    Q5. 没有满盘和棋处理：chooseEasyMove 返回 false 时既不落子、
        也不切换玩家，会卡住（这条按之前的约定先不动）。

  ---------------------------------------------------------------------
  建议 1（收益最大、改动最小）：让它也看对手的棋 —— 攻守兼备
  ---------------------------------------------------------------------
  给 getScore() 增加一个参数 player，表示"评估谁"（原来写死 aiPlayer），
  然后在 chooseEasyMove 里对同一空点分别算"我"和"对手"的分：

        int mineScore = 0;
        int oppScore  = 0;
        for(int d = 0; d < 4; d++){
            mineScore += getScore(row, col, dr[d], dc[d], aiPlayer);
            oppScore  += getScore(row, col, dr[d], dc[d], humanPlayer);
        }
        /* 自家进攻 + 八成的防守价值：这样对手的活三 / 冲四会被优先堵住 */
        int tempScore = mineScore + oppScore * 4 / 5;

  其中 humanPlayer = (aiPlayer == 1) ? 2 : 1。
  效果：简单模式立刻从"不会防守"变成"会堵活三、会堵冲四"。
  说明：原代码是每条方向单独调用再相加，这里把方向表和循环一起补上，
        与原写法等价，只是多算了一遍对手的分。
  可调项：把 4/5 调大（如 9/10）就更偏防守，调小就更偏进攻。

  ---------------------------------------------------------------------
  建议 2：加长观察距离
  ---------------------------------------------------------------------
  AI.h 里的 times 由 4 改成 5。
  原值 4 意味着加上落子本身最多只能识别到 4 连，看不到"落子后成五"；
  改成 5 之后它能判断出真正的五连，杀招识别会明显变准。

  ---------------------------------------------------------------------
  建议 3：修掉"开局只会下左上角"
  ---------------------------------------------------------------------
  a) 把 bestScore 的初值从 0 改成 -1，保证第一个候选点一定会被选中；
  b) 在 chooseEasyMove 开头加一句：棋盘全空时直接返回天元
     （row = col = lines / 2），这是五子棋的常识开局。
  这两处改完，AI 开局不再贴着左上角乱下。

  ---------------------------------------------------------------------
  建议 4：修掉 Q2 的提前退出
  ---------------------------------------------------------------------
  getScore() 里"第一格为空就 break"的写法会让绝大多数点得 0 分。
  更合理的做法是：不要一遇到空位就放弃，而是继续往后看，或者
  改为统计"若在此落子后"两侧各自能连多长（这正是普通模式
  scoreDirection() 的做法，可以直接参考）。
  如果不想大改，至少可以把"第一格为空就直接返回 0"改成
  "第一格为空也给一点基础的活一分"，避免开局全是 0 分。

  ---------------------------------------------------------------------
  建议 5：给 countMultiple 越界加保护
  ---------------------------------------------------------------------
  把 countMultiple 数组从 11 个元素扩到 16 个，或者在取值前加一句：
        if(count > 10){ count = 10; }
  这样长连时不会越界读。

  ---------------------------------------------------------------------
  建议 6：AI 无法落子时不要卡住
  ---------------------------------------------------------------------
  在 main.cpp 的 AI 分支里，chooseEasyMove 返回 false 时应该做点处理：
        if(chooseEasyMove(currentPlayer, bestRow, bestCol)){
            placeChess(bestRow, bestCol, currentPlayer);
            if(!checkWin(bestRow, bestCol, currentPlayer)){
                switchPlayer(currentPlayer);
            }
        }else{
            /* 棋盘已满：不落子，改判和棋或换手，避免卡死 */
            switchPlayer(currentPlayer);
        }
  注意：这条按之前约定属于"平局判定"，需要和另一个修改一起考虑。

  ---------------------------------------------------------------------
  改动量参考
  ---------------------------------------------------------------------
  建议 1 + 2 + 3 只需要动 AI.cpp / AI.h 的几行，就能让简单模式
  从"几乎随机"变成"会进攻也会防守"，性价比最高。
  建议 4、5 属于健壮性修补，建议 6 需要和平局判定一起做。


------------------------------------------------------------------------
 五、如何编译与自测
------------------------------------------------------------------------

 两个 .cpp 都内置了自测代码，用宏开关控制，正常编译工程时不生效。

 普通模式自测（需在 Dev-C++ 的 MinGW64 命令行下）：
     g++ -DAI_NORMAL_TEST ai_normal.cpp -o ai_normal_test.exe
     ai_normal_test.exe

 困难模式自测（会打印剪枝对比统计）：
     g++ -DAI_HARD_TEST ai_hard.cpp -o ai_hard_test.exe
     ai_hard_test.exe

 编译器位置：C:\Program Files (x86)\Dev-Cpp\MinGW64\bin\g++.exe

 本机实测结果：
     普通模式自测 6 项全部通过；
     困难模式自测 7 项全部通过，全程约 1.1 秒。
